# 乘车动态提示（Motion Cues for Android）

给一加 Ace 3（以及其他 Android 8.0+ 手机）用的防晕车圆点，效果类似 iOS 18 的「车辆运动提示」和 Pixel 的 Motion Assist：
屏幕边缘的圆点会跟着车辆的加速、刹车、转弯移动，让眼睛看到的运动和内耳感受到的保持一致。

## 安装

1. 打开本仓库的 **Releases** 页面，下载最新的 `MotionCue-v1.0.x.apk` 并安装（也可以在 Actions 里下载构建产物）。
2. 打开 App，按「还需要几步设置」卡片的提示授予 **悬浮窗** 权限（必需）和其它可选权限。
3. 建议在 ColorOS 中：设置 → 应用 → 乘车动态提示 → 耗电管理 → 打开「允许后台行为」「允许自启动」，防止服务被杀。
4. 打开「运动提示」开关，并选择模式：
   - **始终显示**：上车前打开，最可靠；
   - **自动检测乘车**：检测到乘车约 15 秒后自动显示，走路时自动隐藏（实验性）。
5. 顶部的预览会实时演示圆点效果（服务运行时跟随真实传感器）；也可以点「演示 12 秒」在整个屏幕上看。
6. 可以在下拉控制中心添加「防晕车圆点」快捷开关：关闭 → 始终显示 → 自动。
7. 觉得圆点动得不够明显或太明显，调「灵敏度」即可（0.25–3 倍）。

## 圆点怎么动

把圆点想象成车里没固定住的小球：

| 车辆动作 | 圆点 |
|---|---|
| 加速 | 往下（往后）滑 |
| 刹车 | 往上（往前）滑 |
| 左转 | 往右 |
| 右转 | 往左 |

## 技术实现

- **传感器**：一加 Ace 3 有加速度计、陀螺仪，系统提供融合后的「游戏旋转矢量」（不用磁力计，不受车内磁场干扰）。
  App 用它估计竖直方向，再把屏幕的「右方」「上方」（手机竖着拿时是「往屏幕里」）分别投影到水平面，
  加速度在这两个方向上的分量就是提示量（自动去掉重力）。这等于把车里「没固定的小球」的滑动方向投影到屏幕上，
  所以手机平放、斜拿、竖拿、横屏、躺着举在脸上方（屏幕朝下）都一致正确。陀螺仪在竖直轴上的分量是转弯角速度，
  用来在低速转弯时补充提示。没有旋转矢量的手机会退化为陀螺仪+加速度计互补滤波。
- **滤波**：晕动症最敏感的频段约 0.1–0.5Hz，车辆操控大多低于 1Hz，所以加速度用 1.5Hz 两级低通滤掉路面颠簸和手抖，
  再加 0.08 秒超前补偿抵消滤波延迟；转弯角速度用 0.6Hz 低通，滤掉手的慢速晃动（否则手持时圆点会左右晃）。
  有门限的慢速去偏消除零漂和姿态误差；软死区去掉微小噪声；检测到用户在拿起/转动手机时暂时压低反馈。
- **响应曲线**：位移 ∝ |加速度|^0.7，日常驾驶最常见的轻微加减速（0.3–1 m/s²）也有明显位移，急刹不会冲得太远；
  前后方向增益比左右更大（两侧点列里竖直方向的小位移最不显眼）。
- **动态点阵**：每次加减速、转弯都用三重线索表达，方向与前庭感受完全一致：
  ① 整体滑动（像车里没固定的小球）；② 绽放——运动越强圆点越大、越多（平稳时每侧两列小点，最强时三列大点），
  强度从屏幕边缘逐列向内传播成一道柔和的波，运动结束后慢慢收回；③ 堆积——小球往哪边滑，哪边的点更大更密
  （刹车时上半部分涨起来，左转时右侧涨起来），所以前后方向在两侧点列里也一目了然。
- **圆点样式**：实心圆芯 + 一圈对比色细边；「自动」配色跟随系统深浅色（浅色模式深灰点、深色模式浅色点，切换时实时更新），
  对比色细边保证遇到相反底色时也清楚；运动时拖出由粗到细的彗尾；新长出的点淡入，不会出现灰尘一样的小点。
  可选白色、黑色或跟随系统主题色（Android 12+ 动态取色）。
- **刷新率**：圆点由 `Choreographer` 在每个 VSYNC 驱动，回调频率就是屏幕当前的真实刷新率（60/90/120Hz、LTPO 动态变化都跟随）。
  物理模拟使用真实帧间隔 + 固定 2ms 子步长的临界阻尼弹簧，因此刷新率变化时运动速度和轨迹完全一致，高刷只是更顺滑。
  圆点静止时停止逐帧绘制，屏幕可以降频省电；设置里还可以选择「尽量最高」或「60Hz 省电」向系统投票。
  App 内「实时数据」会显示当前刷新率、支持的刷新率和动画实测帧率。
- **乘车检测**：国行 ColorOS 没有 Google 活动识别 API，App 用振动能量（>3Hz）、步频能量（1–3Hz）/计步器、车辆操控（低频水平加速度/偏航）三个特征加积分迟滞自行判断。
- **圆点场**：一张无限平铺的交错点阵整体随车辆运动平移，再用固定在屏幕上的遮罩只露出边缘带。
  点在边缘带里滑动，越过内侧边界或走到屏幕边缘时平滑淡出、另一侧淡入，所以位移再大也不会飞出屏幕或堆到内容中间。
- **悬浮窗**：「两侧」「四周」布局只在屏幕边缘放几个互不重叠的窄条窗口（`TYPE_APPLICATION_OVERLAY`、不可触摸），
  屏幕中间没有任何悬浮窗，其它 App 中间区域的触摸不会被系统标记为「被遮挡」（银行/支付类密码键盘会拒收被遮挡的触摸）。
  Android 12+ 要求此类窗口不透明度 ≤ 80% 才能让触摸穿透，App 会自动限制；窗口互不重叠，不透明度也不会叠加超标。

## 已知限制

- 普通应用的悬浮窗无法显示在锁屏和部分系统界面之上（Pixel 的系统级实现可以）。
- 「全屏网格」布局（以及点很稀疏时的「四周」布局）会覆盖大部分屏幕，被覆盖区域里有防遮挡保护的输入框可能拒收点击，这时请换回「两侧」。
- Android 15 起，后台靠悬浮窗权限启动服务要求已有可见的悬浮窗：从快捷开关开启时如果被系统拒绝，会闪一下透明页面来启动（把 App 设为「不限制后台耗电」可避免）。
- 自动检测是启发式的，可能会有延迟或误判，可在「实时数据」中查看判断依据。授予「身体活动」权限后会用系统计步器识别走路，更准确。
- 手机绕长轴侧转时（屏幕朝向侧面），提示方向会随屏幕朝向偏转一些，这与头部实际感受到的加速度方向一致。
- 视线方向上的运动在屏幕平面里画不出来；手机竖着拿时约定把它显示为上下移动（正常坐姿下就是前后加减速）。
  侧躺看手机时视线方向是车的左右方向，所以转弯会显示为上下移动。
- 加速度计无法区分「持续很久的轻微加速」和「传感器姿态误差」：例如高铁以约 0.3 m/s² 持续加速一两分钟以上，
  提示会逐渐变弱，结束后圆点会在约半分钟内缓慢回位十几像素。
- 没有授予「身体活动」权限时，步子很轻的走路要约 3 分钟才会退出乘车状态（授予后约 5 秒）。
- 进程被系统杀掉后，Android 15 可能不允许服务在后台自动恢复，这时会出现一条「点此恢复」的通知。
- 仅供乘客使用，驾驶时请勿看手机。

## 构建

```bash
./gradlew assembleRelease
```

每次 push 都会由 GitHub Actions 构建并发布到 Releases。

**签名**：默认使用仓库内公开的 `app/motioncue.keystore`（只为了方便覆盖升级；任何人都能用它签出可覆盖安装的 APK）。
改用私有签名：在仓库 Settings → Secrets and variables → Actions 中添加
`KEYSTORE_BASE64`（keystore 文件的 base64）、`KEYSTORE_PASSWORD`、`KEY_ALIAS`、`KEY_PASSWORD`，工作流会自动使用。
注意：换签名后，已安装的旧版需要先卸载才能装新版。本地构建可直接设置环境变量 `KEYSTORE_FILE` 等。

## 对抗性审查

仓库带有一个 Claude Code 项目级 subagent：`.claude/agents/adversarial-reviewer.md`。
它专门尝试「弄坏」这个 App（各种屏幕方向下的运动方向、刷新率无关性、服务生命周期、Android 14/15 平台规则、构建与签名），
只报告有具体失败场景和证据的问题。在 Claude Code 中改完代码后可以说「用 adversarial-reviewer 审查这次改动」。
